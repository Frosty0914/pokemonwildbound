# Contributing / Development Workflow

This is currently a small in-development fan project.

## Recommended workflow

1. Keep `main` in a known working state.
2. Make substantial work on a feature branch, e.g. `feature/willowmere`.
3. Open a pull request back into `main` when the feature is ready for testing.
4. Use version tags for test builds (`indev-0.0.1`, `indev-0.0.2`, etc.).
5. Do not commit commercial ROM files or extracted copyrighted game assets.
6. Publish binary differences as patch files instead.

## Commit style

Use short descriptive commits, for example:

- `feat: add Willowmere exterior map`
- `feat: script Professor Linden intro`
- `fix: correct title palette`
- `data: rebalance Route 2 encounters`
- `docs: update test instructions`
